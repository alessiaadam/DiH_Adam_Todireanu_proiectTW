SRS — Ierbar Virtual

Versiune: 1.0 — Data: 2026-06-09

Autori: Adam Alessia-Nicoleta, Todireanu Laura-Maria

Rezumat

Acest document prezintă Specificația de Cerințe a Sistemului (SRS) pentru aplicația "Ierbar Virtual". Include cerințele funcționale, nefuncționale, constrângerile, definițiile datelor și cazurile de utilizare. Raportul este furnizat în formă Scholarly HTML pentru publicare pe site-ul proiectului.

1. Introducere

1.1 Scop: SRS-ul descrie funcționalitățile esențiale ale aplicației "Ierbar Virtual" — gestionarea unei colecții de plante, autentificare și autorizare, import/export date și funcționalități administrative.

1.2 Domeniu de aplicare: Aplicație web PHP + MySQL, destinată utilizatorilor și administratorilor pentru catalogarea și consultarea plantelor.

1.3 Definiții: SRS — Software Requirements Specification; UI — Interfață Utilizator; CSV/JSON/XML — formate de date.

2. Descriere generală a sistemului

2.1 Perspective: Sistem web PHP + MySQL cu frontend HTML/CSS/JS și API-uri PHP pentru operațiuni CRUD.

2.2 Funcționalități: Înregistrare/autentificare, adăugare/actualizare/ștergere plante, vizualizare detalii, încărcare media, filtrare și căutare.

2.3 Utilizatori: Utilizator simplu și Administrator (rol `admin`).

2.4 Dependențe: Server web cu PHP+PDO, MySQL, permisiuni `uploads/`.

3. Cerințe Funcționale

  1. F1 — Autentificare: Înregistrare, autentificare și deconectare; protejare rute cu `api/check_auth.php`.
  2. F2 — Gestionare utilizatori (admin): Vizualizare listă utilizatori, vizualizare/ștergere înregistrări (admin).
  3. F3 — CRUD plante: Adăugare (`api/process_add_plant.php`), editare (`api/process_edit_plant.php`), ștergere (`api/delete_plant.php`), vizualizare detalii (`plant_details.php`).
  4. F4 — Media: Stocare imagini/video în `uploads/` și referințe în tabela `media`.
  5. F5 — Import/Export: Import și export CSV/JSON/XML prin `api/import_*.php` și `api/export_*.php`.
  6. F6 — Căutare/Filtrare: Endpoint `api/get_plants.php` suportă filtre și căutare text.

4. Cerințe Nefuncționale

  • Securitate: Sesiuni PHP; verificări roluri server-side; recomandare: hashing parole, input sanitization.
  • Performanță: Răspuns API optim pentru seturi moderate de date; paginare recomandată la listări mari.
  • Compatibilitate: Browsere moderne; PHP 7.4+/MySQL.
  • Fiabilitate: Operațiuni de import în tranzacții pentru consistență.

5. Definiții de date și schema

Schema SQL se regăsește în: database/dih_db.sql. Tabele esențiale:

users(id, name, email, password_hash, role)
plants(id, user_id, common_name, scientific_name, description, origin, status, propagation_method)
media(id, plant_id, file_path, type)
characteristics(id, name, category)
plant_characteristics(plant_id, characteristic_id)

6. Cazuri de utilizare

  1. UC1: Înregistrare și autentificare utilizator.
  2. UC2: Adaugă plantă cu media; sistemul salvează în DB și stochează fișierele.
  3. UC3: Import lot de plante (admin) din CSV/JSON/XML; validare și insert tranzacțional.

7. Constrângeri

  • Necesitate PHP + MySQL; permisiuni scriere pentru `uploads/`.
  • Datele importate trebuie validate (format, câmpuri minime).

8. Criterii de acceptare

  • Flux de autentificare funcțional.
  • CRUD plante testat manual: adăugare/editează/șterge.
  • Import/Export corecte pentru fișiere validate.

9. Referințe

  • IEEE SRS template (adaptare).
  • W3C Scholarly HTML — structurare semantică pentru publicare pe web.
