SRS — Ierbar Virtual

Versiune: 1.0 — Data: 2026-06-09

Autori: Adam Alessia-Nicoleta, Todireanu Laura-Maria

Rezumat

Acest document prezintă Specificația de Cerințe a Sistemului (SRS) pentru aplicația "Ierbar Virtual". Include cerințele funcționale, nefuncționale, constrângerile, definițiile datelor și cazurile de utilizare. Raportul este furnizat în formă Scholarly HTML pentru publicare pe site-ul proiectului.

1. Introducere

1.1 Scop: SRS-ul descrie funcționalitățile esențiale ale aplicației "Ierbar Virtual" — gestionarea unei colecții de plante, autentificare și autorizare, import/export date și funcționalități administrative.

1.2 Domeniu de aplicare: Aplicație web PHP + MySQL, destinată utilizatorilor și administratorilor pentru catalogarea și consultarea plantelor.

1.3 Definiții: SRS — Software Requirements Specification; UI — Interfață Utilizator; CSV/JSON/XML — formate de date.

2. Descriere generală a sistemului

2.1 Perspective: Aplicația este construită cu HTML/CSS/JS nativ pe front-end și PHP + MySQL pe back-end. Interacțiunea browser-server se face prin API-uri PHP.

2.2 Funcționalități generale: gestionare utilizatori, autentificare, administrare plante, filtrare avansată, import/export date și încărcare media.

2.3 Actori: Utilizator obișnuit (adaugă și editează plante proprii) și Administrator (gestionează datele globale și utilizatorii).

2.4 Dependențe: server web Apache/Nginx, PHP 7.4+/8+, extensie PDO, MySQL/MariaDB, permisiune scriere pentru `uploads/`.

2.5 Arhitectură sistem: Browser → HTML/CSS/JS → Fetch API → endpoint PHP (`api/*.php`) → baza de date relațională. Aplicația folosește un design bazat pe servicii Web fără framework-uri externe.

3. Cerințe Funcționale

  1. F1 — Autentificare și autorizare: utilizatorii pot crea cont, se pot autentifica și pot închide sesiunea.
  2. F2 — Modul administrativ: adminul poate vizualiza lista de utilizatori și lista de plante, și poate șterge înregistrări.
  3. F3 — CRUD plante: orice utilizator autentificat poate adăuga, edita și șterge plante proprii; adminul poate gestiona toate plantele.
  4. F4 — Caracteristici plante: plantele au atribute care includ denumiri, descriere, origine, statut, tip sol, metodă de înmulțire și caracteristici multiple.
  5. F5 — Media: se pot încărca imagini și video-uri pentru fiecare plantă, stocate în `uploads/` și referențiate din tabela `media`.
  6. F6 — Căutare și filtrare multi-criterială: utilizatorii pot combina filtru după origine, sol, nume și caracteristici pentru a găsi plante specifice.
  7. F7 — Import/export date: datele pot fi exportate și importate în formatele CSV, JSON și XML.

4. Cerințe Nefuncționale

  • Validitate: interfața este construită cu HTML/CSS valide și responsive.
  • Performanță: interacțiunea API este asincronă și rapidă pentru volume moderate de date.
  • Securitate: protecție contra SQL injection cu PDO prepared statements; escapare XSS la afișarea datelor; verificare server-side a rolurilor.
  • Modularitate: codul este organizat în fișiere separate pentru API, front-end, stiluri și date.
  • Compatibilitate: browser moderne și server PHP standard.

5. Definiții de date și schema

Structura bazei de date este definită în `database/dih_db.sql`. Principalele tabele și relații sunt:

users(id, name, email, password, role)
plants(id, user_id, common_name, scientific_name, description, origin, soil, status, propagation_method)
media(id, plant_id, file_path, type)
characteristics(id, name, category)
plant_characteristics(plant_id, characteristic_id)
related_species(plant_id_1, plant_id_2)

Relații: `plants.user_id` se leagă la `users.id`; `media.plant_id` se leagă la `plants.id`; `plant_characteristics` și `related_species` descriu relațiile complexe dintre plante.

6. Cazuri de utilizare

  1. UC1 — Autentificare: utilizatorul creează cont și se autentifică pentru a accesa dashboard-ul.
  2. UC2 — Adăugare plantă: utilizatorul completează formularul, încarcă media și salvează planta în colecție.
  3. UC3 — Filtrare plante: utilizatorul aplică filtre multiple pentru a obține un subset de plante relevante.
  4. UC4 — Export date: adminul exportă lista de plante în CSV/JSON/XML.
  5. UC5 — Import date: adminul importă un fișier CSV/JSON/XML cu plante în baza de date.
  6. UC6 — Gestionare utilizatori: adminul vizualizează utilizatorii și poate monitoriza accesul.

7. Constrângeri

  • Nu se folosesc framework-uri front-end sau back-end.
  • Comunicarea se realizează prin API-uri Web și Ajax/Fetch.
  • Sunt folosite formate deschise pentru import/export: CSV, JSON, XML.
  • Există un modul administrativ pentru controlul resurselor aplicației.

8. Criterii de acceptare

  • Autentificarea și înregistrarea funcționează corect.
  • CRUD pentru plante funcționează și este protejat prin permisiuni.
  • Dashboard-ul permite căutare și filtrare multi-criterială.
  • Exportul și importul CSV/JSON/XML funcționează.
  • Există modul administrativ pentru utilizatori și plante.
  • Interfața este responsive și construită fără framework-uri.
